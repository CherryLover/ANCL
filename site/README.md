# 天衍阅读站

《我把现代文明传回了修仙界》原文与续写线的在线阅读站。纯静态，无框架、无依赖、无构建工具链，只有一个 Node 脚本负责把仓库里的文本打包成可托管的目录。

视觉稿来自 Claude Design 的「天衍阅读站」，这里是它的可部署实现。

## 目录说明

```
site/
├── build.mjs           构建脚本：扫描仓库文本 → 生成 dist/
├── serve.mjs           本地预览用的极简静态服务器
├── site.config.json    站点文案、资料清单、图集占位配置
├── src/
│   ├── index.html      页面外壳
│   └── assets/
│       ├── app.js      路由、阅读器、搜索、Markdown 渲染
│       └── styles.css  全部样式与云海 / 墨夜两套配色
├── images/             （可选）插画目录，放进去自动上墙
└── dist/               构建产物，不进版本库
```

## 本地跑起来

```bash
node site/build.mjs && node site/serve.mjs
```

然后打开 http://127.0.0.1:8765/ 。

构建脚本会顺带做几件检查，并把结果打在终端里：章节序号是否连续、文件名标题与正文首行标题是否一致、有没有不符合命名规则的文件。

## 站点功能

- **首页**：A/B/C 三条内容线的说明、章节与字数统计、资料入口、图集占位。
- **目录**：按 50 章一组分页，标出每章已有的内容线。
- **阅读**：在原作、第一版续写和第二版续写之间切换；同章可与原作左右对照。
- **搜索**：默认按标题和章号匹配；点「全文检索」会分批拉取全部正文，边扫边出结果，命中处高亮。
- **资料**：`写作准备/` 下的 Markdown 直接在站内渲染，资料之间的相互引用会自动变成站内跳转。
- **阅读设置**：字号 15–26px、三档行距、云海 / 墨夜两套配色，全部记在浏览器本地。

## 新增章节

把文件按原有规则放进 `章节正文/` 就行，站点不需要任何改动：

```
A-0256_第256章 章节标题.txt     原作者更新
B-0256_第256章 章节标题.txt     第一版续写
C-0320_第320章 章节标题.txt     第二版续写
```

- `A-` 表示原作者正文，`B-` 表示第一版续写，`C-` 表示第二版续写。
- 连字符后的四位数字是真实章号，也是站内排序和配对的唯一依据。
- 同一个章号存在多个内容线文件时，该章自动出现版本切换和左右对照。
- 正文第一行仍然写 `第256章 章节标题`。

推到 main 之后 GitHub Action 会自动重建并发布，索引、目录、统计、上下章、搜索范围都会跟着更新。

### 章号写错了怎么办

站内一律以文件名前四位为准。如果某个文件的 `第N章` 与前缀对不上（原稿第 143、230 章就是这种情况），构建脚本会自动在该章顶部挂一条说明，不需要手工维护。

## 加插画

在 `site/images/` 下放图片，构建时会复制到 `dist/data/images/`：

- `footer.jpg`（或 png/webp）：页脚横幅，会顶掉那个虚线占位框。
- 图集四张图的文件名写在 `site.config.json` 的 `gallery` 里，放了哪张就显示哪张，没放的继续留占位。
- 资料页顶部配图在 `site.config.json` 的 `docImages` 里按资料名配置。

## 部署

GitHub Action（`.github/workflows/deploy-site.yml`）在 main 有相关改动时自动跑：构建 → 把 `site/dist` 的内容强推到 `gh-pages` 分支。

仓库 Settings → Pages → Source 选 `gh-pages` 分支、根目录，即可访问。

### 自定义域名

域名写在 `site.config.json` 的 `domain` 字段，构建时会生成 `CNAME` 文件。

**必须走这里配，不能只在 GitHub 页面上填**：gh-pages 分支每次部署都是整个重建的，如果 `CNAME` 不是构建产物，下一次部署就会把它删掉，GitHub 那边的自定义域名会跟着失效。

DNS 侧需要一条记录：

```
类型    CNAME
名称    ai-novel
目标    cherrylover.github.io
代理    DNS only（灰云）
```

用 Cloudflare 橙云代理也能通，但 GitHub 申请 Let's Encrypt 证书期间必须先灰云，否则验证会失败。证书签发完再决定要不要开代理。

手动部署也一样简单，`site/dist` 是自包含的，扔进任何静态托管都能跑：

```bash
node site/build.mjs
npx gh-pages -d site/dist   # 或者手工推分支
```

## 数据格式

构建产物里的 `data/index.json`：

```jsonc
{
  "meta":  { "heroTitle": [...], "origMax": 250, "gallery": [...] },
  "docs":  [{ "name": "主要人物", "desc": "…" }],
  "notes": { "143": "原稿此章的章号误写为…" },
  "chapters": [
    { "f": "0001", "s": "orig", "n": 1, "t": "长老救命", "c": 2530 }
  ]
}
```

`f` 是正文文件名（对应 `data/chapters/f.txt`），`s` 是来源，`n` 是章号，`t` 是标题，`c` 是字数。两条线用同一个 `n` 配对。
